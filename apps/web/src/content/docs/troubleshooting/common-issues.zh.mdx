# 常见问题

使用 Wemux 时可能遇到问题的解决方案。

## Worker 问题

### Worker 显示离线

**症状**：尽管守护进程正在运行，Worker 在仪表板中显示离线。

**解决方案**：

1. 检查守护进程是否正在运行：
   ```bash
   ps aux | grep wemux-worker
   ```

2. 重启守护进程：
   ```bash
   Wemux worker daemon
   ```

3. 检查到控制面的网络连接：
   ```bash
   curl http://127.0.0.1:8989/health
   ```

### Worker 未收到任务

**症状**：任务停留在队列中，Worker 保持空闲。

**解决方案**：

1. 验证 Worker 已配对到正确的项目
2. 检查 Worker 状态显示"已连接"或"空闲"
3. 查看 Worker 控制台中的日志
4. 确保 Worker 有足够的资源

### 配对码不被接受

**症状**：输入配对码返回错误。

**解决方案**：

1. 代码在 5 分钟后过期 - 生成新代码
2. 确保您在正确的项目中输入代码
3. 检查是否有拼写错误或多余空格
4. 尝试生成新代码

## 任务执行问题

### 任务卡在进行中

**症状**：任务停留在"进行中"状态而不完成。

**解决方案**：

1. 检查执行日志中是否有错误
2. 点击**"接管"**停止任务
3. 使用更新的指令重试
4. 检查 Worker 资源（CPU、内存）

### 执行失败并报错

**症状**：任务显示"失败"状态并显示错误消息。

**解决方案**：

1. 审核执行日志中的错误
2. 常见原因：
   - 仓库访问问题
   - 缺少依赖项
   - AI 模型超时
   - Worktree 创建失败
3. 修复根本原因
4. 重试任务

### AI Agent 无响应

**症状**：Worker 忙碌但日志中无活动。

**解决方案**：

1. 检查 AI 模型 API 是否响应
2. 验证 API 密钥设置正确
3. 检查模型速率限制
4. 接管并手动运行

## 仓库问题

### 克隆失败

**症状**：任务失败并显示"git clone"错误。

**解决方案**：

1. 验证仓库 URL 正确
2. 检查 Worker 是否有 SSH 访问权限（如果使用 SSH）
3. 确保仓库存在且可访问
4. 检查是否有防火墙阻止 git 端口

### Worktree 创建失败

**症状**：创建 Git worktree 时出错。

**解决方案**：

1. 检查 Worker 上的磁盘空间
2. 清理旧的 worktree：
   ```bash
   wemux-worker cleanup
   ```
3. 检查 Git 版本是否最新
4. 确保没有冲突的分支

## 配置问题

### 环境变量未加载

**症状**：设置更改无效。

**解决方案**：

1. 更改后重启 Worker 守护进程
2. 验证 env 文件位置：`~/.wemux/worker.env`
3. 检查文件中的语法错误
4. 使用 `wemux worker status` 查看已加载的配置

### 模型不可用

**症状**：任务失败并显示模型相关错误。

**解决方案**：

1. 验证 API 密钥已设置且有效
2. 检查模型名称是否正确
3. 确保账户有权访问该模型
4. 暂时尝试不同的模型

## Preview 问题

### Preview 一直显示“连接中”或无法建立隧道

**症状**：右侧 Preview 面板一直停留在“连接中”，或者显示 tunnel / websocket 连接失败。

**解决方案**：

1. 确认 Worker 仍然在线，并且当前工作区绑定到了正确的执行节点
2. 点击 **“刷新”** 或重新点击 **“连接 Preview”**
3. 检查源应用地址是否仍然是本地 HTTP 地址，例如 `http://localhost:3000/`
4. 如果是 hybrid / Docker 开发环境，确认 Worker 实际能访问控制面地址，而不是错误地回到容器自己的 `localhost`

### Preview 显示“已连接”，但页面空白或只有一行错误文本

**症状**：Preview 状态显示“已连接”，但 iframe 中没有正常页面，只显示空白、`fetch failed`、`ECONNREFUSED`，或很短的一行错误。

**这通常意味着**：

- Preview tunnel 已经连通
- 但源应用本身没有成功响应
- 问题已经不在 Wemux 隧道，而在工作区里的开发服务器

**解决方案**：

1. 查看底部终端输出，确认应用是否真的成功启动
2. 在当前 Worker 环境内直接访问源应用地址，例如 `http://localhost:3000/`
3. 如果终端里出现 `fetch failed`、`ECONNREFUSED`、`GET / 500`、字体下载失败等错误，优先修复源应用本身
4. 修复后点击 Preview 面板上的 **“刷新”**

### Vite / TanStack Start 项目在容器或远程 Worker 中无法打开 Preview

**症状**：本地终端看起来显示 “ready”，但 Preview 里仍然访问不到 `http://localhost:3000/`。

**常见原因**：

Vite 开发服务器默认可能只监听 `localhost`。如果应用运行在 Docker 容器、远程 Worker、或浏览器与开发服务器不在同一网络命名空间里，Preview 代理可能无法从 Worker 环境访问它。

**解决方案**：

1. 启动时显式暴露 host：
   ```bash
   npm run dev -- --host 0.0.0.0
   ```

2. 如果你使用 `pnpm`：
   ```bash
   pnpm dev -- --host 0.0.0.0
   ```

3. 也可以直接修改项目脚本：
   ```json
   {
     "scripts": {
       "dev": "vite dev --host 0.0.0.0 --port 3000"
     }
   }
   ```

4. 然后重新点击 **“连接 Preview”** 或 **“刷新”**

**适用范围**：

- Vite
- TanStack Start
- 以及其他基于 Vite dev server 的前端项目

### Next.js 项目 Preview 返回 500

**症状**：Preview 已连通，但终端里出现 `GET / 500`，或者字体、远程资源请求失败。

**常见原因**：

- 项目在启动时依赖外网资源，例如 `next/font/google`
- 当前 Worker 环境无法访问这些外部资源

**解决方案**：

1. 查看终端里失败的远程请求地址
2. 如果是 Google Fonts、外部 API、CDN 等资源不可达，改用本地资源或移除外网依赖
3. 修复后重新启动开发服务器，再刷新 Preview
