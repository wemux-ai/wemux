# Worker

Worker 是执行 AI Agent 并在真实仓库中执行任务的执行器机器。

## 什么是 Worker？

Worker 是已配对的机器（本地 Mac、Linux 机器、VM 或云实例），可以：

- 运行 Wemux Worker 守护进程
- 从控制面接收任务分配
- 在隔离的 Git worktree 中执行 AI Agent
- 将执行日志、分支和产物报告回系统

## Worker 架构

```
┌─────────────────────────────────────────────────────┐
│                   控制面                             │
│                 (Wemux Server)                   │
└─────────────────────┬───────────────────────────────┘
                      │ 任务、命令、状态
┌─────────────────────▼───────────────────────────────┐
│                   Worker 守护进程                    │
│               (您的机器 / VM)                       │
├─────────────────────────────────────────────────────┤
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐  │
│  │   OpenCode  │  │     MCP     │  │     Git     │  │
│  │    Agent    │  │   Servers   │  │   Worktrees │  │
│  └─────────────┘  └─────────────┘  └─────────────┘  │
└─────────────────────────────────────────────────────┘
```

## Worker 状态

| 状态 | 含义 |
|-------|---------|
| **已连接** | 守护进程运行并与控制面通信 |
| **空闲** | 已连接并准备接收任务 |
| **忙碌** | 正在执行任务 |
| **离线** | 守护进程未运行或无法访问 |

## 配对 Worker

1. 在您的机器上安装 Worker 守护进程
2. 使用 `wemux worker daemon` 启动守护进程
3. 打开 Wemux Web 界面
4. 导航到项目 **Worker** 选项卡
5. 点击**"添加 Worker"**生成配对码
6. 在 Worker 控制台中输入代码
7. 确认连接状态

## 能力配置

每个 Worker 可以有一个能力配置，描述：

- **可用模型** - 此机器上可以运行哪些 AI 模型
- **MCP 服务器** - 预配置的 MCP 服务器连接
- **环境** - 预安装的工具和依赖项
- **资源限制** - CPU/内存约束

系统使用这些配置将任务路由到适当的 Worker。

## Worker 运行位置

Worker 可以在以下位置运行：

- **本地 Mac/Linux 机器** -最适合个人开发
- **共享办公机器** - 用于团队范围执行
- **云 VM** - 用于资源密集型或 GPU 工作负载
- **私人服务器** - 用于安全敏感环境
