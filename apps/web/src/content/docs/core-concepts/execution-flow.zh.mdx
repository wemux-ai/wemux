# 执行流程

Wemux 将任务通过受控执行管道从输入到交付进行路由。

## 执行管道

```
任务输入 → 路由 → 执行 → 审核 → 交付
```

### 1. 任务输入

定义具有清晰边界的工作：

- **标题** - 需要完成的事情
- **描述** - 自然语言需求
- **验收标准** - 如何验证完成
- **范围边界** - 包含和不包含的内容

### 2. 路由

系统确定在哪里以及如何执行：

- **Worker 选择** - 路由到具有正确环境的机器
- **Agent 选择** - 选择适当的 AI Agent（OpenCode 等）
- **分支策略** - 为任务创建隔离的 worktree

### 3. 执行

Worker 执行工作：

1. 使用隔离分支创建 Git worktree
2. 将仓库克隆到 worktree
3. 使用任务指令运行 AI Agent
4. 执行代码、运行测试、创建产物
5. 将变更提交到任务分支
6. 报告日志、分支名称和产物

### 4. 审核

批准前的的人工监督：

- 审核执行日志
- 检查分支和变更的文件
- 验证验收标准是否满足
- 批准、请求更改或接管

### 5. 交付

最终确定和发布：

- 合并分支（手动或自动）
- 清理 worktree
- 归档任务记录

## 执行模式

| 模式 | 描述 |
|------|-------------|
| **自动选择** | 系统选择最佳可用 Worker |
| **指定执行器** | 路由到特定 Worker 机器 |
| **混合** | 本地启动，如果需要则委托到云端 |

## 人工干预

Wemux 保持人工负责：

- **任务创建** - 人工定义需求
- **Worker 分配** - 人工或系统可以路由
- **执行监控** - 实时日志可见性
- **审核和批准** - 人工决定什么可以合并
- **接管** - 人工可以在任何时候接管控制

## 返回内容

执行产生：

- **分支名称** - 带有变更的 Git 分支
- **提交历史** - 执行期间的所有提交
- **执行日志** - 完整的终端输出
- **产物** - 构建的文件、测试结果、截图
- **审核备注** - AI 生成变更摘要
